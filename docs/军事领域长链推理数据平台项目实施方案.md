# 军事领域长链推理数据平台项目实施方案

**版本**：0.2
**日期**：2026-09-09
**项目性质**：军事领域训练数据基础设施建设项目

## 1. 项目定义

### 1.1 项目名称

军事领域长链推理大模型训练数据制备平台项目。

### 1.2 项目定位

为军事领域经授权的训练准备、战备保障、战时支援记录、战后复盘和联合演训知识处理场景建设训练数据基础设施，支撑：

- 经审查资料的归档、解析、去重、脱敏、标注和版本化；
- 文本、扫描文档、图像、图表、表格和图文交错页面的数据制备；
- LoRA 领域适配和 GRPO 可验证奖励后训练；
- 独立评测、数据污染防护、生产问题样本受控回流、审计和撤回。
- 陆海空等军兵种及联合保障条线的数据关联；
- 有人、无人和有人/无人协同平台的运行、维护、训练和安全检查资料治理。

### 1.3 严格不在项目范围内

本项目不建设和不支持：

- 实时态势感知、目标识别、目标选择、目标跟踪；
- 兵力部署、作战计划、战术推演、指挥控制；
- 武器使用、打击建议、行动优化或自动决策；
- 未授权受控资料、敏感个人信息、实时情报或规避监管能力；
- 面向外部用户的自动化军事决策服务。

任何输入疑似属于上述范围，平台必须执行阻断、隔离、升级人工审核或拒绝处理。战前/战时标签只表示资料阶段，不构成自动行动授权。

## 2. 项目目标与成功标准

### 2.1 总体目标

建立一套可在内网/受限环境部署、面向开发人员可实现、面向审核人员可操作、面向训练人员可复现的数据平台，使训练数据从来源到模型运行具备完整证据链。

### 2.2 目标结果

1. 建成来源、许可、用途、风险、保留期和撤回台账；
2. 建成文本和多模态文档解析流水线；
3. 建成自动质量/去重/污染/PII 门禁与人工审核闭环；
4. 建成 LoRA 和 GRPO 两类数据包导出器；
5. 建成数据契约、OpenLineage 血缘、审计、评测和生产回流机制；
6. 在经授权、脱敏且覆盖战前/战时保障/战后复盘、多军兵种和有人/无人平台的黄金集上完成低成本数据配方对照实验；
7. 通过上线前合规、可复现、灾备、撤回和安全演练。

### 2.3 成功标准

- 已发布数据快照来源与处理链可追溯率 100%；
- 发布快照中未授权、过期、撤回资产为 0；
- 训练/评测已确认重复为 0；
- LoRA/GRPO 数据包可依据 manifest 重建；
- GRPO 奖励和验证器能够回放；
- PII 高敏/低置信命中不自动放行；
- 生产 trace 不自动进入训练；
- 独立评测在不牺牲安全、合规和稳定性的前提下超过基线；
- Git、镜像、模型、规则和数据契约均有版本记录。

## 3. 实施原则

1. **军事领域明确分级**：项目和数据标签覆盖战前、战时保障、战后复盘、多军兵种以及有人/无人协同；所有研发样例必须经授权、脱敏和用途审查。
2. **先治理再扩量**：没有授权、数据契约、审计和撤回能力，不进入规模化采集。
3. **小样本先证伪**：先用小规模代理训练淘汰无效策略，再购买计算资源扩大规模。
4. **自动化做确定性工作**：哈希、规则、解析、结构校验和可复验奖励优先自动化。
5. **人工做高价值判断**：人工聚焦许可不明、边界样本、模型分歧、低置信和高影响样本。
6. **离线优先**：内网部署默认不向外发送输入文件、原始文本、图像或提示。
7. **无审计不发布**：任何数据、模型、规则或评测结果无法追溯即不得进入下一阶段。

## 5. 分阶段计划与里程碑

> 具体日历时间应由项目经理根据人员到岗、数据授权和基础设施条件排定；下表采用“阶段/退出门禁”而不是虚构固定日期。

| 阶段 | 主要产出 | 退出门禁 |
|---|---|---|
| P0 立项与合规基线 | 项目章程、范围、数据分级、角色矩阵、开源台账 | 业务、合规、安全共同签字；军事场景黄金集准备完成。 |
| P1 数据与平台骨架 | 资产台账、对象存储、元数据、权限、审计、基础血缘 | 能导入一批样例并追溯到原件；阻断未授权资产。 |
| P2 文档处理 MVP | 文本/PDF/图片/表格解析、PII、质量、去重、审核 | 黄金集达到约定解析/结构指标；离线运行通过。 |
| P3 LoRA 数据闭环 | 监督样本、数据契约、LoRA 导出、代理训练和独立评测 | 数据包可重建；评测无确认污染；基线可复现。 |
| P4 GRPO 数据闭环 | 候选组、验证器、RewardSpec、奖励回放、GRPO 导出 | episode 100% 可回放；奖励漂移和硬约束告警有效。 |

| P6 正式验收 | 运维、测试、审计、培训、交付清单 | 所有 Go/No-Go 门禁通过，形成版本基线。 |

| ML/训练工程师 | LoRA、GRPO、RewardSpec、实验与评测 | P3-P6 |

### 6.2 资源预算口径

不预设不可靠的绝对金额，按以下资源项核算：

- 人力：按角色人月、专家标注小时和审核小时计量；
- 存储：原件、派生对象、embedding、快照、checkpoint、日志和备份容量；
- 计算：OCR CPU/GPU 小时、embedding GPU 小时、LoRA/GRPO GPU 小时、评测推理小时；
- 工具：数据库、对象存储、监控、CI/CD、模型仓库和漏洞扫描；
- 合规：授权核查、脱敏复核、第三方依赖审查和安全测试；
- 风险储备：返工、污染重建、组件替换和撤回再训练。

每轮数据策略实验必须报告：候选数量、通过数量、人工分钟、CPU/GPU 小时、存储增量、独立评测增益和每评测点成本。

## 7. 质量门禁与验收

### 7.1 数据准入门禁

- 来源、许可证/授权、用途、保留期和责任人完整；
- 军事阶段、军兵种、平台形态和授权等级已标记，行动化高风险内容已隔离；
- 原件哈希和存储位置完成登记；
- PII、敏感用途、版权和数据风险检查通过或进入隔离；
- 不与任何训练/验证/测试/隐藏集发生确认重复。

### 7.2 数据包发布门禁

- schema/freshness/quality assertions 通过；
- 数据卡、manifest、处理链、代码 commit、模型/规则版本齐全；
- LoRA 配置或 GRPO RewardSpec 已冻结；
- 样本、证据、许可证、审批和血缘可回溯；
- 安全/合规指标不回归；
- 数据 steward、训练负责人、合规审核员完成审批。

### 7.3 系统验收场景

1. 未授权资产导入后自动隔离，不能生成训练包；
2. 受限军事领域输入命中策略后阻断，不产生行动化输出；
3. 扫描文档从样本可追溯到页图、OCR、表格和人工修订；
4. 训练和评测近重复命中后冻结数据版本；
5. PII 低置信/高敏命中进入人工审核；
6. LoRA 数据包可由 manifest 重建；
7. GRPO candidate group 和 RewardSpec 可重放；
8. 生产 trace 只能进入独立评测快照，不能直接进入训练；
9. 撤回源资产能列出所有下游样本、数据包、训练运行、模型和评测影响；
10. OpenLineage 事件包含正确的 START/COMPLETE/FAIL 和 input/output。

## 8. 风险、依赖与应对

| 风险 | 触发信号 | 应对措施 | 责任人 |
|---|---|---|---|
| 数据授权不足 | 许可缺失、用途冲突、撤回请求增加 | 白名单、阻断、法律/合规审查、撤回影响图 | 数据管理员/合规 |
| 敏感内容混入 | 高风险标签、人工升级、规则命中 | 分级策略、隔离队列、专门黄金集、禁止自动放行 | 安全审核员 |
| OCR/表格错误 | CER/WER 或结构 F1 低、模型引用错误 | 双轨保留原图；关键字段人工复核；按文档类型切换解析器 | 数据工程师 |
| 数据污染 | n-gram/语义/视觉命中、检测器不一致 | 多检测器、隐藏评测集、疑似即隔离、重建版本 | 评测负责人 |
| 奖励投机/塌缩 | 零方差组、人工推翻率升高、KL 漂移 | 固化 RewardSpec，增加规则验证和难例，暂停 GRPO | ML 工程师 |
| 内网组件不兼容 | 模型下载失败、容器漏洞、离线构建失败 | 预下载、镜像签名、SBOM、离线 CI、替代组件 | DevSecOps |
| 资源超预算 | GPU/人工成本超过门槛 | 小规模筛选、缓存、分层处理、停止劣质数据策略 | 项目负责人 |
| 生产反馈污染 | trace 未脱敏、直接写训练库 | trace 隔离、独立评测、人工确认、审批回流 | 平台负责人 |
| 领域目标漂移 | 任务边界变化、评测分布漂移 | 变更控制、数据卡、版本化黄金集、重新审批 | 产品/领域负责人 |

## 9. 变更控制

任何下列变更必须创建变更单并完成影响评估：

- 军事领域数据范围、敏感等级或允许用途变化；
- 数据源、许可证、模型权重或第三方依赖变化；
- OCR/解析器、去重器、污染检测器、PII 检测器变更；
- LoRA 目标层、GRPO RewardSpec、验证器、judge prompt 或采样配置变化；
- 评测集、阈值、数据契约、权限和保留策略变化；
- 新增任何连接外部网络的组件或远程模型服务。

变更必须更新：架构/需求/数据卡、测试计划、血缘和审计；高风险变更需要回滚方案和安全审核员签字。

## 10. 上线、运行和撤回

### 10.1 上线前

- 完成所有数据和软件供应链清单；
- 完成内网/离线部署验证和出口审计；
- 完成备份恢复、密钥轮换、漏洞扫描和权限审计；
- 完成数据污染、PII、敏感边界、奖励回放和撤回演练；
- 冻结版本 manifest 和 Git commit。

### 10.2 试点观察期

- 仅开放受控角色和经授权、脱敏数据；
- 生产 trace 只用于脱敏评测，不直接训练；
- 每日查看阻断、审核、质量、成本、污染和奖励漂移；
- 每个数据版本保留回滚点和前一可用版本。

### 10.3 撤回流程

1. 接收授权撤回、隐私请求、风险事件或质量事故；
2. 将源资产标记为 `WITHDRAWN`，阻断新的导出和训练；
3. 沿血缘查找派生对象、数据快照、LoRA/GRPO 运行、评测和部署工件；
4. 生成影响清单和处置决定；
5. 重新构建或限制使用受影响版本；
6. 写入 tombstone、审计事件和复盘报告。
